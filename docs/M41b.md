## 2026-08-04 — § II.3c: the variance reduction that wasn't

**The pre-registered check was unrunnable, for a reason worth recording.**
All 3,245 `runs/*.jsonl` on this box carry only `{job, pair, results}` with
bare win/loss ints — **zero** carry a margin. The plan's premise was right
that `_engine_game` captures the end state (`stats["final"]`, deck counts and
prizes remaining) and that `_from_a_view` re-keys it to side a; what nobody
had noticed is that `_pair_worker` returned only the result ints, so the
margin died at the multiprocessing boundary. Every `--workers` battery ever
run discarded it. `--diag` shows it because that path is single-process.

Fixed: margins now persist per chunk, **index-aligned** with results (a slid
margin would pair an outcome with another game's margin — the silent
corruption this milestone is about, so `_pair_worker` pads and truncates to
`len(chunk)` and a mutation test confirms a one-game slide fails). Old
checkpoints have no `margins` key and still resume; that is pinned too.
Cost: ~0.55s per 100 games (~10%), the `perf_counter`-per-move price of the
stats dict.

**Then a fresh 2,000-game cell settled it — against the recommendation I made
in the review.** `retain_b:alakazam_v2_h4` vs `m39_bc_grim:grim_live`,
n=2,000, workers 8, seed 1:

| estimator | win rate | 95% half-width | bootstrap SD (4,000 reps) |
|---|---|---|---|
| raw binomial | 0.7150 | ±0.0198 | 0.00990 |
| margin-adjusted (CUPED-style) | 0.7150 | ±0.0103 | **0.00990** |
| seat-stratified | 0.7150 | ±0.0197 | 0.00990 |

The margin correlates **+0.853** with the outcome and the naive residual
interval reads **47.9% narrower** — and the point estimate is identical to
`0.00e+00`, with the bootstrap giving all three estimators the *same* SD to
five decimals. The adjustment is an **algebraic no-op**: CUPED needs a
covariate measured before the treatment and independent of the arm, and the
prize margin is a same-game post-outcome quantity that a stronger arm
improves. With `E[X]` taken in-sample, `mean(Y - t(X - mean(X))) == mean(Y)`
exactly. The 47.9% is not a variance reduction; it is the same estimator
wearing a smaller error bar. **Dropped, per the pre-registered consequence** —
and the review recommendation that proposed it is corrected in the plan.

Worth stating plainly: this is the harness catching a defect *in the harness
design*, one milestone before it would have decided Stage B.

**The constructive half.** Seat is fixed by the slot-fair design — before any
game, independently of the arm — so seat-stratified variance is legitimate
where margin adjustment is not. Implemented and reported; worth **nothing on
this cell** (seats 0.7295 vs 0.7005, true SD unchanged), so not adopted. It
is there if a future cell shows a real split.

**And the finding that actually decides Stage B: n is cheap.** 2,000 games in
**1m46s** at workers 8 (~19 games/s). For 80% power on the plausible 3.5pp
effect a two-arm comparison needs **n ≈ 3,200 per cell ≈ 3 minutes**. The
fallback the plan treated as the expensive branch is cheaper than the hedge
it was hedging with. Stage B runs at n ≥ 3,000, pinned in the § II.3d spec.

New instrument `scripts/m41b_gate_estimator.py` with 6 fixtures
(`tests/test_gate_estimator.py`) — the no-op asserted as the algebraic
identity it is, the bootstrap pinned to refuse crediting the illusion, and a
margin-free legacy checkpoint pinned to FAIL loudly rather than return a
silent zero that looks like a verdict.

## 2026-08-04 — § II.3d: the bar cannot move after the numbers land

`scripts/gate_spec.py` (`hash` / `run` / `decode`) replaces the fork-a-decoder
habit — eight `*_decide.py` and counting, each putting the bar in the same
file as the numbers. The spec's canonical hash covers arms, beds, n, seed and
bars but not prose, so reformatting or rewording is not tampering while any
decision-relevant edit is. `run` stamps that hash into every battery
checkpoint header via the new `run_pairs(key_extra=...)`, which makes the
**existing** header-mismatch refusal do the work — no new trust mechanism.

`decode` refuses before reading a number when the stamped hash differs, a
cell is short of the pre-registered n, a cell is missing, or the battery is an
unstamped legacy file; between the bars it reports INCONCLUSIVE rather than
rounding up. Verified end to end on the real engine: an honest run decodes
(arm 0.7400 ±0.0608 vs control 0.0800 ±0.0376, z 13.42, PASS), and moving the
pass bar 0.05 → 0.90 afterwards refuses with no verdict — as does shrinking n
after the fact. `m40_decide.py` is deliberately untouched: it holds the
pre-registered live-mix weighting and stands as the record of what shipped.

## 2026-08-04 — § II.3e: the guards travel with the dangerous action

No hosted CI exists here, so "CI" is the suite plus the QC replay review, and
both were things a human remembered to run. Two structural changes:

**The export gates itself.** `tcg.shipping.verify_bundle` checks what is
verifiable from the bundle alone — twin parity, artifacts present, deck size
and identity, module-level bundle purity — and `export` now raises
`BundleError` instead of leaving a shippable bundle. That is the M41 defect
(an export ran mid-edit and shipped a half-finished encoder, caught by a QC
sweep that could easily have passed) closed structurally rather than
procedurally. The corpus-dependent Tier-1 checks stay in `ship_verify.py`.

**One command before anything consequential.** `scripts/ci_gate.py`: suite +
bundle + instruments, ~11 s, one PASS/FAIL line. The 4 known failures are
tolerated **by name**, never by count, so a new failure cannot hide in the
allowance — and the allowance itself complains if a known failure starts
passing. `scripts/qc_battery.py` runs it first and aborts with exit 1 rather
than spending a mandatory human replay review on a stale artifact.

Negative controls, both fired: a planted failing test is reported as a NEW
failure by name; a one-line drift in `submission/rl/combat.py` fails the
bundle tier and stops the run before the instrument tier.

**The purity check caught itself, and that is the useful part.** Its first
draft searched for the substring `import polars` and immediately flagged
`rl/encoders.py` — where the import sits under `if _PARQUET.exists()`
precisely so it never fires on Kaggle. A gate that fails every healthy export
gets switched off, so it now parses the AST and flags only module-level
imports; the false positive is pinned as a regression test. Two milestones
after M42's six instrument corrections, the new instrument's first act was to
produce a seventh and get caught by its own fixtures.

## 2026-08-04 — Stage B0: the divergence rate, and the question it raised

`scripts/m41b_divergence_probe.py` installs `matchrunner.SOLVED_STATS` and
reads what `wrap_with_solver` has always counted. On
`solved:m39_retain_b:alakazam_v2_h4` vs the grim bed, 40 games, 2,815 prompts:

| quantity | count | rate |
|---|---|---|
| prompts | 2,815 | — |
| solver fired | 151 | 5.36% of prompts |
| **action CHANGED** | **77** | **2.74% of prompts** |
| changed given fired | — | 50.99% |

Per tier: T2_trainer_gap triggered 651 / fired 131 (the bulk of the signal),
T4_closing 88 / 19, T1_ko_one_attach 1 / 1.

So a composite-labelled corpus carries **~27 teacher rows per 1,000 prompts**;
the other 97.3% is the student's own argmax. That is just above the 2% bar the
probe pre-registers as SPARSE, so uniform cross-entropy is defensible — but
the corpus must be sized on the DIVERGENT count, not the prompt count (~16k
divergent rows needs ~590k prompts ≈ 8,400 games), and divergence weighting
stays worth an arm.

**Then the prior question.** The memory of M40's finding is that the composite
wrap is *inert against our own pilot*, while the +125 ELO (M40 S3) was
measured clone-vs-clone. Stage B distils a teacher into a student — so the
number that actually gates the work is neither of those: it is whether
`solved:retain_b` outplays `model:retain_b` **on our own deck**. If it does
not, there is no teacher edge to transfer and the collect+train must not be
spent. Measured before building any collector, as a pre-registered hashed
gate (spec `a4d3c4fe5e2f67ea`, n=3,000/cell, beds grim + wall, pass +0.05 /
kill 0.00) — the first real use of § II.3d.

### Result 1 — the SHIPPED-latency teacher: INCONCLUSIVE

| bed | arm (composite) | control (bare net) | delta | z |
|---|---|---|---|---|
| grim | 0.7083 ±0.0163 | 0.7155 ±0.0161 | **-0.0072** | -0.61 |
| wall | 0.3313 ±0.0168 | 0.2930 ±0.0163 | **+0.0383** | 3.20 |
| POOLED | 0.5198 ±0.0126 | 0.5042 ±0.0127 | **+0.0156** | 1.71 |

Between the bars, so the pre-registered outcome is "we do not know" — not a
rounded-up pass. Two things worth keeping:

* **The effect is heterogeneous by bed.** The composite is worth a solid
  +3.8pp against the wall clone (z=3.20) and nothing at all against grim
  (-0.7pp). Pooling those into "+1.6pp" hides the only real signal in the
  cell. Whatever the teacher knows, it is knowledge the wall matchup rewards.
* **The n decision is vindicated.** Half-widths came in at ±1.6pp, matching
  the § II.3c arithmetic almost exactly. At the historical n=400 the same
  cell would have read ±4.9pp and been unreadable in either direction — this
  gate is only decidable because the harness phase raised n first.

**Caveat that reframes the result:** this arm is the DEFAULT `solved:` budget,
120 nodes / 50 ms — tuned to keep the *shipped* agent under the G6 latency
gate (mean move < 50 ms). M40 S3 measured its +125 ELO at
`solved:...:800:400`. A distillation teacher runs offline and is never served,
so the latency constraint does not bind it. Result 1 therefore answers "would
wrapping the shipped agent help", which is a real question but not Stage B's.
Re-run at full budget as spec `fb458ddebf14c0c6`.

### Result 2 — the FULL-budget teacher (800/400): also INCONCLUSIVE, and no better

| bed | arm (composite) | control (bare net) | delta | z |
|---|---|---|---|---|
| grim | 0.6993 ±0.0164 | 0.7215 ±0.0160 | **-0.0222** | -1.89 |
| wall | 0.3367 ±0.0169 | 0.2933 ±0.0163 | **+0.0433** | 3.61 |
| POOLED | 0.5180 ±0.0126 | 0.5074 ±0.0127 | **+0.0106** | 1.16 |

**6.7x the nodes and 8x the deadline bought nothing.** Pooled went DOWN
(+1.56pp -> +1.06pp) versus the cheap teacher; the wall gain grew a little
(+3.83 -> +4.33pp) and the grim regression roughly tripled (-0.72 -> -2.22pp).
Whatever the solver contributes on our deck, it is not search-depth-limited —
which also means a slower teacher is not a better label source, and the
collection cost argument for a big budget disappears.

### What the pair actually establishes

1. **The teacher edge is matchup-specific, not general.** The wall gain is
   stable and real across two independent budgets (z=3.20 and z=3.61); the
   grim effect is negative in both (-0.72, -2.22pp). Pooling opposite-signed
   effects into "+1.1pp" is precisely the M38 mistake the weighted-pool law
   was written for — an honest gate that still measured the wrong thing.
2. **It is negative where the live loss mass actually is.** Live forensics
   put grim at the TOP of the loss families; the composite makes grim worse
   at both budgets. A general distillation would be transferring a
   regression into our most expensive matchup.
3. **The retention arithmetic finishes it.** At the measured BC retention of
   0.20 (M40 X5), a +1.06pp teacher edge yields a **~0.2pp** student gain.
   Detecting that at 80% power needs ~1,000,000 games per cell. Even the
   wall-only edge (+4.33pp -> ~0.87pp in the student) needs ~53,000
   games/cell just to MEASURE. **Stage B's expected effect is below what this
   project can afford to measure**, let alone ship.

**Pre-registered verdict on both specs: INCONCLUSIVE** (pooled deltas sit
between the bars). The bars are not moved retroactively — but the decision
they inform is clear, and it is the one BACKLOG #10 was designed to buy: a
day spent instead of a month.

**What survives, and it is not nothing.** The wall result is a genuine,
twice-replicated +4.3pp behavioural difference. That is a forensics lead, not
a distillation target: the useful next question is WHAT the solver does
differently in the wall matchup, which `scripts/m42_perception_probe.py` and
the divergence probe can answer in an afternoon, and whose answer would land
as a rule or an encoder feature — the cheap consumption path — rather than a
corpus and a retrain.

## 2026-08-05 — chasing the wall lead, and finding something larger

`scripts/m41b_wall_probe.py` records, on every prompt where the solver
overrides, WHAT the net played versus what the solver played. Piotr's call
was to chase the wall lead; the lead turned out to point somewhere else.

**The rate is not the story.** Divergence is 3.04% on wall vs 2.74% on grim —
essentially the same. **The TIER is:** `T1_ko_one_attach` triggers 26 times
on wall and once on grim (fires 22 vs 1). The wall clone's high-HP bodies
manufacture "a KO is one attach away" positions; grim does not.

**But the dominant swap is the same in BOTH beds, and it is not about walls:**

| swap | grim | wall |
|---|---|---|
| `<setup move>` -> `ATTACK(dmg=0)` | 22 of 50 | 10 of 56 |

`ATTACK(dmg=0)` is the printed damage from `_ATK`. Card **743** (Alakazam) has
exactly one attack, id 1072, printed **0**, and `rl.scaling.SCALING_ATTACKS`
records it as `('hand', 20, 0)` — 20 damage per card in hand. The solver runs
the engine forward model, so it sees the real number; the net reads the
printed table, so it sees zero and does setup instead. This is M41's founding
defect, still live.

### The census that reframes the milestone

Every checkpoint on the box, all 98:

| trained option width | checkpoints |
|---|---|
| 90 (v1) | 25 |
| 94 (v3) | 19 |
| **100 (`OPTION_M28_DIM`)** | **47** |
| **anything above 100** | **0** |

**No net has ever been trained at a width that can see the M41 energy-ceiling
block (100-104), the M42 perception block (105-114), or the M41b block
(115-142).** Forty-three columns, three consecutive milestones, all built,
column-safe, census-clean — and all truncated away by
`OptionScorerV3.forward` on every net in play. M42's own diary said it
plainly and it did not land: *"the shipped net reads columns 0-99 and will
not see any of it."*

So the solver's edge is not exotic search knowledge. It is substantially the
value of features **we have already built and never trained on**, bought at
inference time by a search the shipped agent cannot afford.

### What this changes

1. **Stage B is correctly abandoned, but for a sharper reason than "the
   teacher is weak".** Distilling the composite would spend a corpus and a
   retrain to teach the net a behaviour its own inputs could state directly —
   if any net were trained wide enough to read them.
2. **The width retrain is the highest-value next experiment**, and it is now
   evidence-backed rather than merely "the next decision" the plan parked. It
   is still an EXPERIMENT: that the net will learn what the columns say is a
   hypothesis, not a measurement, and the M39 dose/retention laws still bind.
3. **One dead-end may deserve the epoch treatment.** M39's "imitation is
   exhausted for the 900+ band" was measured at width 100 — i.e. on an
   encoder blind to scaling damage, live board state, typed cost and matchup.
   That is the same shape of argument §15's epoch amendment makes about the
   inverted leaf: a law measured on a substrate that no longer exists. Not a
   claim that the law is wrong — a claim that it is untested on the current
   inputs, and cheap to re-test as part of the retrain.

## 2026-08-05 — R1/R2: the machinery to consume the columns

**R1, the widening warm start.** `rl.plan_iter.widen_option_dim(sd, target)`
generalises `load_v3h_into_v3o` / `load_v3o_into_v3m`, which were copied once
per milestone because one block was appended per milestone; the census found
three at once. Verified on the real champion: `cont3` 100 -> 143, trained
columns preserved, appended columns exactly zero, embedding block shifted,
+11,008 params (43 x 256).

*The invariant, stated at the precision it holds.* The weight copy is exact,
but narrow and wide run GEMMs of different SHAPE, so the reduction order
differs: max |logit diff| **1.49e-08** (~8x below float32 eps), value head
exactly equal, argmax and full ranking identical. "Day one is exactly
equivalent" — the phrase inherited from the earlier warm starts — is true
behaviourally and false bitwise. Pinned as ranking identity, since every
pilot argsorts.

*The hazard guard.* `_refuse_mixed_option_widths` aborts a widening run on
mixed-width shards: `BCDatasetV3`'s pad shim zero-fills the narrow ones,
which is right for the legacy blocks and a LIE for the appended ones — it
would assert the new features are 0 where they are not and quietly
manufacture the null the experiment exists to test.

**R2, the corpus — a re-encode, not a collection.** The shards store
PRE-ENCODED options (`options (N, 100)`), so the existing corpora are frozen
at the old width. But the raw source survives: 3,391 cached kaggle episodes
(322 MB) and `rl/replay_bc.py` encodes from them directly. Re-running the
champion recipe — recorded in the corpus's own `deck_registry.json`
(min_score 800, winners-only, deck hash `9294d9d8`, hand-aware) — produced
**5 shards / 23,115 decisions / 203,589 options at width 143**, more than

**The control corpus is the same corpus, sliced.** `m41b_slice_corpus.py`
truncates to width 100: identical rows, labels, order and shard boundaries,
differing in exactly one thing. That is exact rather than approximate because

**The experiment, so a null is readable.** Arm = `cont3` widened, trained on

Two observations that the pooled number hides, recorded as analysis and NOT
as a verdict:

* **The gains sit on the live loss families.** grim (+2.2pp, z=1.90) and
  dragapult (+2.3pp, z=2.74) are the top TWO families in the live forensics;
  the only negative cell is wall, and it is not significant (z=-0.91). This
  is the M38 weighted-pool lesson pointing the other way for once — an
  unweighted pool *understates* a result concentrated where the live mass is.
* **It is the mirror image of the solver composite.** That arm was -2.2pp on
  grim and +4.3pp on wall; the columns are +2.2pp on grim and -1.1pp on wall.
  Whatever the two mechanisms are doing, they are not the same thing, and
  they are strongest on opposite matchups.

**What it is not yet: a claim.** This is ONE training draw per arm, and G-13
measured a 10-12pp spread across clones of a single corpus. A +1.1pp
difference between two single draws cannot be separated from the training
lottery. Replication across seeds is the next step, not a bigger claim about
this one — and it exposed that `plan_iter train` had **no seed control at
all**, so reruns reproduced the same draw and independent draws were
impossible. Added (`--seed`, pinning torch and numpy), which also makes any
training run reproducible for the first time.

### What this establishes

**43 columns of encoder work across three milestones pay +2.45pp**, and the
gain is concentrated on grim (+3.5pp) and dragapult (+2.8pp) — the top TWO
live loss families. The result has an unusually clean provenance: same
checkpoint, same rows, same epochs, same seed per pair, differing in exactly
one thing — whether the columns exist. `init val_acc` was identical (0.662)
in all six trainings, so the warm start cannot be the explanation.

It also closes the loop on the census: the solver's edge WAS substantially
the value of unseen features. Given them directly, the net gets at inference
cost zero what the composite was paying 0.4 s/turn of search for — and gets
it on every prompt, not the 2.7% where a trigger fires.

**One law needs re-testing, now with evidence rather than an argument.**
M39's "imitation is exhausted for the 900+ band" was measured at width 100.
The same corpus, same recipe and same lineage just moved +2.45pp when the
encoder could see more — so the law is about the SUBSTRATE, not about
imitation. It should carry an epoch-style note like §15's.
