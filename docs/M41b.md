## 2026-08-04 — § II.3c: the variance reduction that wasn't

**The pre-registered check was unrunnable, for a reason worth recording.**
All 3,245 `runs/*.jsonl` on this box carry only `{job, pair, results}` with
bare win/loss ints — **zero** carry a margin. The plan's premise was right
that `_engine_game` captures the end state (`stats["final"]`, deck counts and
prizes remaining) and that `_from_a_view` re-keys it to side a; what nobody
had noticed is that `_pair_worker` returned only the result ints, so the
margin died at the multiprocessing boundary. Every `--workers` battery ever
run discarded it. `--diag` shows it because that path is single-process.

Fixed: margins now persist per chunk, **index-aligned** with results (a slid
margin would pair an outcome with another game's margin — the silent
corruption this milestone is about, so `_pair_worker` pads and truncates to
`len(chunk)` and a mutation test confirms a one-game slide fails). Old
checkpoints have no `margins` key and still resume; that is pinned too.
Cost: ~0.55s per 100 games (~10%), the `perf_counter`-per-move price of the
stats dict.

**Then a fresh 2,000-game cell settled it — against the recommendation I made
in the review.** `retain_b:alakazam_v2_h4` vs `m39_bc_grim:grim_live`,
n=2,000, workers 8, seed 1:

| estimator | win rate | 95% half-width | bootstrap SD (4,000 reps) |
|---|---|---|---|
| raw binomial | 0.7150 | ±0.0198 | 0.00990 |
| margin-adjusted (CUPED-style) | 0.7150 | ±0.0103 | **0.00990** |
| seat-stratified | 0.7150 | ±0.0197 | 0.00990 |

The margin correlates **+0.853** with the outcome and the naive residual
interval reads **47.9% narrower** — and the point estimate is identical to
`0.00e+00`, with the bootstrap giving all three estimators the *same* SD to
five decimals. The adjustment is an **algebraic no-op**: CUPED needs a
covariate measured before the treatment and independent of the arm, and the
prize margin is a same-game post-outcome quantity that a stronger arm
improves. With `E[X]` taken in-sample, `mean(Y - t(X - mean(X))) == mean(Y)`
exactly. The 47.9% is not a variance reduction; it is the same estimator
wearing a smaller error bar. **Dropped, per the pre-registered consequence** —
and the review recommendation that proposed it is corrected in the plan.

Worth stating plainly: this is the harness catching a defect *in the harness
design*, one milestone before it would have decided Stage B.

**The constructive half.** Seat is fixed by the slot-fair design — before any
game, independently of the arm — so seat-stratified variance is legitimate
where margin adjustment is not. Implemented and reported; worth **nothing on
this cell** (seats 0.7295 vs 0.7005, true SD unchanged), so not adopted. It
is there if a future cell shows a real split.

**And the finding that actually decides Stage B: n is cheap.** 2,000 games in
**1m46s** at workers 8 (~19 games/s). For 80% power on the plausible 3.5pp
effect a two-arm comparison needs **n ≈ 3,200 per cell ≈ 3 minutes**. The
fallback the plan treated as the expensive branch is cheaper than the hedge
it was hedging with. Stage B runs at n ≥ 3,000, pinned in the § II.3d spec.

New instrument `scripts/m41b_gate_estimator.py` with 6 fixtures
(`tests/test_gate_estimator.py`) — the no-op asserted as the algebraic
identity it is, the bootstrap pinned to refuse crediting the illusion, and a
margin-free legacy checkpoint pinned to FAIL loudly rather than return a
silent zero that looks like a verdict.
