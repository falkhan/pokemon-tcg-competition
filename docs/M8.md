# M8 — Beat the ship agent (setup-play campaign): implementation diary

**Status:** 🚧 Active (started 2026-07-12, branch `feature/m8`). Spec:
[M8-plan.md](M8-plan.md). Opened by the M7.4b L4 go/no-go review
([M7.md](M7.md) 2026-07-12).

## Why

The agent doesn't build positions: trainer/item/stadium usage, within-turn
sequencing (discard-then-retrieve, fetch-basics-before-evolutions), bench and
energy development for future turns. Two PPO attempts failed with the same
rise-then-decay signature — but the warm start (`osv2_bc.pt`) turned out to be
cloned from the play-tier-bugged teacher, confounding every conclusion. M8
re-measures first, then attacks setup play on four fronts (solver dev tier,
clean BC, shaped PPO probe, L4 instruments), each in ≤1–2 h legs with
kill/continue gates.

**Campaign bar:** any agent ≥ 0.55 vs `solver:lucario` at n ≥ 800, zero G1
crashes, latency within G6, then the ship gate suite.

## Conventions

- One dated entry per leg — including kills: hypothesis, exact command,
  n/seed, numbers, verdict, routing decision.
- Decide on n=400 (±5pp) minimum, n=800 (±3.5pp) for ship calls; never n=100.
  Fresh recorded seed per leg.
- Record the SOLVER VERSION every number was measured against (M8.1 changes
  the bar itself).
- Deck-agnostic rule: new scoring/shaping terms use `rl/combat.py` /
  `_race_features`-style deck-blind math; lucario is only a CLI argument.
