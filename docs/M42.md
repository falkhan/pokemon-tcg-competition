### 1 + 3 — the cap the rule pilot cannot reach

`score_attach` tier 3 (`rl/generic_pilot.py:432`, twin `tcg/pilot.py:391`) is
the only over-attach cap anywhere in the codebase:

    if _turns_to_ready(target, opp_active, board_ids=my_board_ids) == 0:
        best_cost = min(c for d, c in damaging if d == best_dmg)
        surplus = len(target.energies or ()) - best_cost
        return 600 + bonus - 150 * min(max(surplus, 0), 3)

It is soft (-150 per surplus, floored at 150, never a ban), and on any
printed-0 attacker it is **unreachable**: `_turns_to_ready` routes through
`_charged_best`'s `if dmg <= 0: continue` and returns 99 forever. That is the
same single `if` M41 traced through seven features — it also silently disables
the one anti-over-attach rule the pilot has. Tier 2 fails the same way first:
`_ATK[a][0] > 0` classifies a printed-0 scaler as a 400 "non-attacker".

And the mirror defect, on the same lines: past its printed 3-cost, Teal Mask
Ogerpon ex trips that surplus penalty for **correct** play. This is exactly the
false positive Piotr killed in the forensics on 2026-08-03 (`docs/M41.md:1006`)
— the fix went into `rl/postmortem.py` and never into the pilot, so the
instrument now disagrees with the agent it measures.

### 2 — hand-size scaling is genuinely absent

The only hand-scaling signal in the whole feature set is FEAT col 35
`has_variable_attack`, built in `notebooks/deck_analysis.ipynb` as

    any("x" in a.text or "for each" in (a.text or "").lower() for a in atks)

— one bit, ORed over a card's attacks, undifferentiated between energy-scaling,
hand-scaling and bench-scaling, and true for 181 cards. My own hand size exists
as a bare scalar at state index 1625 and only in the v4 encoder. There is no
option x state interaction term, which is precisely the shape the M28 block's
own comment calls expensive for this two-tower net to form and cheap to hand
over. `_marginal_energy_damage` (`rl/encoders.py:521`) passes `hand_size=0` by
construction, and `nominal_damage` substitutes a constant
`NOMINAL_UNITS["hand"] = 8` against a measured mean hand at attack time of 17.

### 4 — the stadium is not obscured

Contrary to the initial read, the net sees the stadium's full 36-column card
identity pooled at state 126-161, `stadiumPlayed` at 1621, and the M27 option
precondition `is_stadium AND no stadium in play` at option col 95. What is
missing is stadium **effect** in the damage model (Festival Grounds letting
Dipplin attack twice, Lively Stadium) and any stadium reasoning at all in the
rule pilot, where `state.stadium` appears exactly once — as a zone in
`card_at`'s dict. Stadium **ownership** is not recoverable from the observation
(`rl/determinize.py:56` skips it as ambiguous), so the only stadium fact
available with no effect model is identity-match against the one in play.

### 5 — the guard exists, and leaks three ways

`fetch_value` (`tcg/pilot.py:136-157`, twin `rl/generic_pilot.py:96-117`)
already scores an evolution whose basis is nowhere at `FETCH_DEAD_EVOLUTION =
60`. But:

1. it fires only in `KEEP_CONTEXTS` = {TO_HAND, LOOK, NOT_MOVE} — not in
   `PROMOTE_CONTEXTS`;
2. 60 is a soft score, above the 0 an unresolvable option gets, so it is a
   demotion and not a ban;
3. the basis pool counts the **active's** name, so Piotr's exact trigger — 0
   benched Pokemon **and** 0 basics in hand — is not a condition anywhere in
   the codebase.

The `DISCARD_CONTEXTS` mirror is the unguarded half: `-card_usefulness(card.id)`
is basis-blind, so a live basic can be pitched over a dead evolution.

**The shipped neural agent has no coverage at all.** `apply_play_overrides`
returns early on any non-MAIN context (`rl/plan.py:690`), so every search
submenu — `TO_HAND`, `LOOK`, the promote prompts — is raw argmax over net
logits with no rule and no feature describing basis availability.

Worth stating plainly: **this defect is inert on the current ship.**
`submission/deck.csv` is the Ogerpon list, 4x Teal Mask Ogerpon ex and zero
evolutions. It bites on the Alakazam / lucario / dragapult-class decks in
`decks/`, which is where it has to be measured.

### Found, recorded, not fixed: the option target-resolution bug

`rl/encoders.py:207` and `:717` resolve an option's `inPlayArea` /
`inPlayIndex` target against `your_index` rather than `opt.playerIndex`:

    tgt = _card_id_at(state, opt.inPlayArea, opt.inPlayIndex, your_index)

Correct for ATTACH / EVOLVE / tool attachment, which only ever address our own
board. Any option that addresses the **opponent's** board through `inPlayArea`
encodes *our* Pokemon at that index into columns 53-88 instead. Fixing it would
move columns inside every trained width — a silent live policy change — so
Phase 1 carries a counter that settles whether it is a live defect or a
theoretical one, and the fix, if warranted, is a separate ship.

### Scope, agreed with Piotr before any code

Probes + rule-pilot fixes + neural capability. **No collect, no train, no
ship.** Turning `scaling=True` on for `enumerate_plans`, the race block, the
threat model and the solver teacher remains the next bet — it changes what the
TEACHER believes and cannot be evaluated without a fresh corpus.

The order is measure-then-fix, and it is not stylistic. Four instruments in M41
read flat-damage semantics and produced a confident wrong answer; three levers

## 2026-08-04 — CORRECTION: the stadium number was a per-prompt artifact, and the live ship is clean

The entry above reported `stadium_ignored` at 85.4% / 86.8% / **64.6%** and
called it "the only ladder that fires on the shipped agent". **That was wrong,
and the instrument was wrong in the way this milestone exists to catch.**

Caught by cross-checking the new `[stadium-ignored]` post-mortem flag against
the probe. The flag read **zero** on the M41 Ogerpon QC replays while the probe
read 58.5% on the same deck. One of them had to be broken, so I read the
replays directly rather than picking the number I preferred:

    ep_g000_a0.json  turns with the option: [7, 11]   played on: [7, 11]
    ep_g002_a0.json  turns with the option: [5, 11]   played on: [5, 11]

The ship played its stadium on **every turn the option existed**, 4 for 4. The
flag was right; the probe was counting per PROMPT. A turn holds many MAIN
prompts, so playing the stadium at prompt 5 left prompts 1-4 recorded as
declines — inflating the rate by roughly 5x. `rl/postmortem.py:250` had already
committed to the correct semantics four milestones ago: *"fixing it later in
the same turn is fine; ending the turn in the bad state is the failure."* The
probe simply did not inherit it.

## 2026-08-04 — Phase 2: the scaling table, derived from the engine's own text (6 -> 63)

`rl/scaling.py` curated **6** of the pool's ~174 scaling attacks; the rest read
as their printed base, which is <=30 for 142 of them. The module's own
docstring says free-form English "cannot be parsed reliably", and that was the
right call for a damage ESTIMATE. But the text is regular and every number in
it is printed on the card:

    "This attack does {N} more damage for each {X}."   -> base = printed
    "This attack does {N} damage for each {X}."        -> base = 0
    "Place {N} damage counters on your opponent's
     Active Pokemon for each {X}."                     -> per_unit = 10 x N

Mode, per-unit AND base all come out mechanically. That is extraction, not
estimation, and the distinction is the whole argument — every damage GUESS in
this lane has been falsified.

**63 entries, 15 modes.** Seven modes are new: `opp_bench`, `opp_hand`,
`all_bench`, `dmg_counters_self`, `dmg_counters_opp`, `prizes_taken_us`,
`prizes_taken_opp`.

### The acceptance test, and where it had to bend

The plan pre-registered "the parse must reproduce all 6 curated entries
exactly". It reproduces **4 of 6 exactly and independently** — Powerful Hand
`(hand, 20, 0)`, Myriad Leaf Shower `(both_nrg, 30, 30)`, Do the Wave
`(bench_only, 20, 0)`, Syrup Storm `(team_nrg, 30, 30)`. The other two are not
parser failures; they are the parser correctly refusing to guess:

* **560 Rocket Rush** counts "your Team Rocket's Pokemon in play", a NAMED
  SUBSET. The curated entry approximates it as the whole board on a deck fact
  ("these lists are ~all Team Rocket's") that is not in the text.
* **608 Erasure Ball** scales on "each card you discarded in this way" — a cost
  paid INSIDE the attack, so the unit is a choice not yet made at scoring time.
  The curated entry pins the 1-discard middle case.

Forcing the parser to reproduce those would have meant teaching it to make
judgement calls. Instead `_HUMAN_OVERRIDES` names both with the reason, and
`derive_scaling_table()` merges **under** the curated table so a curated entry
can never be overwritten. The test pins the override set at exactly `{560, 608}`
so neither can be quietly promoted to "derived".

### Allow-list by construction

A unit phrase produces an entry only when it FULLY matches a known mode.
Anything qualified, named, conditional or self-referential yields nothing and
falls through to printed damage — the status quo. That direction is the safe
one: a missing entry under-rates a scaling attacker, a wrong entry invents
damage. 16 pinned reject cases cover coin flips, `discarded in this way`,
`placed in this way`, self-referential counts (`United Wings`, `Round`), named
subsets (Team Rocket's / Iono's / Ancient / Stage 2 / Pokemon ex), discard-pile
and Tool and Special-Condition counts, and every damage REDIRECT.

The redirect list earned its own regression. An early draft matched a bare
`of your opponent's benched pok` to catch Blizzard Burst's spread clause — and
it also killed the legitimate `opp_bench` unit of Ogre Comeback, silently
dropping 4 real entries. Every alternative now carries its `to ...` preposition.
Caught only because the pinned snapshot count moved.

Sentence-by-sentence parsing matters too: Voltage Burst is "does 50 more damage
for each Prize card your opponent has taken. This Pokemon also does 30 damage
to itself." — the first sentence is the attack, the second is not.

### Testing around a stubbed engine

`tests/conftest.py` replaces `cg` with a 10-card stub whose attacks carry no
rules text, so under pytest `derive_scaling_table()` sees nothing and
`SCALING_ATTACKS` collapses to the curated six. That silently invalidated an
existing assertion: `test_the_table_covers_exactly_the_documented_entries`
asserted `set(SCALING_ATTACKS) == set(EXPECTED_OWNER)` and **still passed**,
because it was pinning the stub rather than the table. Renamed and re-pointed
at `CURATED_ATTACKS`, which is what it always meant.

The real table is pinned in a SUBPROCESS against the real engine (the
`tcg/decklab.py` smoke-runner precedent) — per-mode counts, total, the six
curated surviving the merge, and five independently re-derived spot cases.

`NOMINAL_UNITS["hand"]` 8 -> **17**, the measured mean hand at attack time.
8 was a guess made before that number existed. The neighbouring entries are
deliberately conservative mid-game values, but this one is a measurement, and
shading it down would re-introduce the bias M41 diagnosed.

### Ship safety, proven rather than argued

`rl/scaling.py` is bundled, and `encode_option_v2` reaches it on every ATTACH
option, so a 10x wider table is a live-code change until proven otherwise.
`scripts/m42_column_safety.py` re-encodes real options from local replays and
digests columns `[0, width)`:

    encoded 23,409 real options (3,506 ATTACH, 1,097 ATTACK, ...)
    columns [0,100) digest 9b4603c33bd7e86676e321460b3812a6   before
    columns [0,100) digest 9b4603c33bd7e86676e321460b3812a6   after
    PASS: bit-identical

The M41 append-and-slice proof, now a command instead of a one-off. Suite:
**1041 passed**, same 4 pre-existing failures.

## 2026-08-04 — CORRECTION 2, and the finding that reframes the milestone: these are NEURAL defects

Two more instrument bugs in `dead_basis_fetch`, then the measurement that
explains all of it.

### The two bugs

**(a) A benched Kadabra does not need an Abra.** Widening the basis check to
PROMOTE contexts turned every `TO_ACTIVE` / `SWITCH` promotion of a benched
evolution into a "dead fetch". Diagnosed by area: **every** PROMOTE pick was
`area=BENCH` — a Pokemon already in play, already evolved. 14 of 19. A rule
written against those would have refused to promote a benched attacker after a
KO: bench-out risk in exchange for nothing.

**(b) A multi-select that takes everything has declined nothing.** The
"alternative existed" rung counted live options *including ones we also
picked*. Instrumented the actual scores at each flagged prompt: every one had
`best_unpicked == 60` (`FETCH_DEAD_EVOLUTION` — every alternative equally
dead) or `nopts == 1`. The pilot was choosing correctly at every single
"defect".

**Corrected: `dead_basis_fetch` on the rule pilot is 0 of 29 and 0 of 9. Killed.**
`fetch_value` already works. The "PROMOTE scope gap" was 100% artifact, and the
36-of-47 diagnosis in the first Phase 1 entry is withdrawn.

### The reframing

Every probe so far ran a RULE pilot, or the Ogerpon neural ship whose deck
makes four of five ladders structurally impossible. Piotr's QC observations
came from neither: they came from the **Alakazam neural ship**. Running that
cell — `model-c-pkg:m39_retain_b:alakazam_v2_h4`, the M40 Ship B config —
against the same grim opponent:

| ladder | **neural alakazam** | rule alakazam | rule lucario | ogerpon ship |
|---|---|---|---|---|
| `over_attach` | **29 / 297 (9.8%)** | 0 / 122 (0.0%) | 1 / 90 (1.1%) | situation 0 |
| `hand_scaler_blind` | **330 / 330 (100%)** | 41 / 41 | situation 0 | situation 0 |
| `retreat_stranded` | 0 / 29 | 0 / 3 | 0 / 23 | situation 0 |
| `dead_basis_fetch` | **4 / 33 (12.1%)** | 0 / 29 | 0 / 9 | situation 0 |
| `stadium_ignored` | **5 / 10 (50%)** | 1 / 10 (10%) | 2 / 5 (40%) | 0 / 23 |

**The defects are the net's, not the heuristics'.** On the identical deck and
the identical opponent, the rule pilot over-attaches 0.0% and the net 9.8%; the
rule pilot takes a dead evolution 0.0% and the net 12.1%; the rule pilot leaves
the opponent's stadium up 10% of the turns it could displace it and the net
50%.

This is the M41 pattern reproduced from a different direction. M41 measured the
same defect at 4.7% in the BC corpus, 5.4% across rival ladder pilots and 33.7%
in our shipped clone, and concluded "a 7x amplification of a defect the
training data does not contain — the net cannot represent a distinction its
inputs hold constant." Here the teacher itself is measured at **0.0%** on the
same board states. The heuristics already encode every one of these rules. The
net does not inherit them, because the features it reads do not carry them.

The concrete cost is measurable now: **440 damage forgone** across those 29
surplus attaches, because each one spends a card out of Alakazam's own damage
formula.

### What this does to the plan

Phase 4 (rule-pilot fixes) was scoped against rule-pilot defect rates that have
now all gone to zero. It shrinks to the one item that is a **correctness bug
regardless of current behaviour**: `score_attach`'s surplus cap is unreachable
on any printed-0 attacker, and `_attach_recipient_value` drops `scaling`. Those
matter because the rule pilot is the TEACHER and the solver's move-ordering —
its damage model feeds the corpus the net learns from — not because it is

## 2026-08-04 — Phase 3: the M42 perception block, 105 -> 115

Ten appended option slots, one per thing the Phase-1 probe measured the NET
getting wrong on the Alakazam ship while the rule pilot, same deck and same
opponent, got right.

| slots | option type | what it says |
|---|---|---|
| 0-4 | ATTACK | live effective damage (scaling resolved against the real board), how much the printed number understates it, scales-on-HAND, scales-at-all, KO-now judged on effective damage |
| 5 | ATTACH | the damage this attach COSTS when our attacker's formula is its own hand size |
| 6-8 | CARD | evolution basis available / absent, and how many basics we can actually bench |
| 9 | PLAY | this stadium would displace the OPPONENT'S |

Design notes worth keeping:

**Slots 6 and 7 are two flags, not one signed feature.** "Not an evolution" and
"a dead evolution" must not share a value with "a live one".

**Slot 5 could not live in the M41 block.** Slot 4 there asks what one more
energy BUYS; for a hand-scaler the answer is 0 while the true marginal value is
NEGATIVE, because the energy card leaves the hand. 440 damage forgone across 29
surplus attaches, measured.

**Slot 9 exists because M27's column 95 is exactly 0 in the situation that
matters** — it reads "is a stadium AND none is in play". Ownership comes off
`Card.playerIndex`, and a same-name replacement reads 0 because it is illegal.

**`_percept_stadium` asks `_play_kind()`, not a CardType int.** That helper's
own comment records that the fake engine numbers CardType differently and a
silent int collision would encode the wrong precondition — the first draft here
used a CardType comparison and read 0 through the entire test suite.

**`_board_units` supplies every count; `_marginal_energy_damage` still supplies
none.** They ask opposite questions, and `effective_damage`'s
defaults-to-0-then-`max(printed, …)` shape is what keeps a hand-mode attack
from inventing damage in the energy-only caller.

### The stub had no evolution cards at all

given**, so cards 1-10 still carry no such attributes and every
