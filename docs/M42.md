## 2026-08-03 — Phase 0: the review, and three of the five are not what they looked like

The ask was "these values are obscured to the pilot, or incorrectly encoded".
Read against the code, that is true of **one** of the five in the way it was
phrased, partly true of two, and false of one — and the two partial cases are
worse than "missing", because the information is present and the code that
consumes it is wrong.

| # | Defect | Neural pilot | Rule pilot | Forensics |
|---|---|---|---|---|
| 1 | over-attach vs cost/retreat | **encoded, invisible** — option cols 100-104 exist; every bundle slices `[:100]` (`rl/policy.py:207`) | **has a cap that cannot fire** | fixed in M41 |
| 2 | hand-size scaling | **absent everywhere** | **misclassifies it** as a non-attacker | none |

### 1 + 3 — the cap the rule pilot cannot reach

`score_attach` tier 3 (`rl/generic_pilot.py:432`, twin `tcg/pilot.py:391`) is
the only over-attach cap anywhere in the codebase:

    if _turns_to_ready(target, opp_active, board_ids=my_board_ids) == 0:
        best_cost = min(c for d, c in damaging if d == best_dmg)
        surplus = len(target.energies or ()) - best_cost
        return 600 + bonus - 150 * min(max(surplus, 0), 3)

It is soft (-150 per surplus, floored at 150, never a ban), and on any
printed-0 attacker it is **unreachable**: `_turns_to_ready` routes through
`_charged_best`'s `if dmg <= 0: continue` and returns 99 forever. That is the
same single `if` M41 traced through seven features — it also silently disables
the one anti-over-attach rule the pilot has. Tier 2 fails the same way first:
`_ATK[a][0] > 0` classifies a printed-0 scaler as a 400 "non-attacker".

And the mirror defect, on the same lines: past its printed 3-cost, Teal Mask
Ogerpon ex trips that surplus penalty for **correct** play. This is exactly the
false positive Piotr killed in the forensics on 2026-08-03 (`docs/M41.md:1006`)
— the fix went into `rl/postmortem.py` and never into the pilot, so the
instrument now disagrees with the agent it measures.

### 2 — hand-size scaling is genuinely absent

The only hand-scaling signal in the whole feature set is FEAT col 35
`has_variable_attack`, built in `notebooks/deck_analysis.ipynb` as

    any("x" in a.text or "for each" in (a.text or "").lower() for a in atks)

— one bit, ORed over a card's attacks, undifferentiated between energy-scaling,
hand-scaling and bench-scaling, and true for 181 cards. My own hand size exists
as a bare scalar at state index 1625 and only in the v4 encoder. There is no
option x state interaction term, which is precisely the shape the M28 block's
own comment calls expensive for this two-tower net to form and cheap to hand
over. `_marginal_energy_damage` (`rl/encoders.py:521`) passes `hand_size=0` by
construction, and `nominal_damage` substitutes a constant
`NOMINAL_UNITS["hand"] = 8` against a measured mean hand at attack time of 17.

### 4 — the stadium is not obscured

Contrary to the initial read, the net sees the stadium's full 36-column card
identity pooled at state 126-161, `stadiumPlayed` at 1621, and the M27 option
precondition `is_stadium AND no stadium in play` at option col 95. What is
missing is stadium **effect** in the damage model (Festival Grounds letting
Dipplin attack twice, Lively Stadium) and any stadium reasoning at all in the
rule pilot, where `state.stadium` appears exactly once — as a zone in
`card_at`'s dict. Stadium **ownership** is not recoverable from the observation
(`rl/determinize.py:56` skips it as ambiguous), so the only stadium fact
available with no effect model is identity-match against the one in play.

### 5 — the guard exists, and leaks three ways

`fetch_value` (`tcg/pilot.py:136-157`, twin `rl/generic_pilot.py:96-117`)
already scores an evolution whose basis is nowhere at `FETCH_DEAD_EVOLUTION =
60`. But:

1. it fires only in `KEEP_CONTEXTS` = {TO_HAND, LOOK, NOT_MOVE} — not in
   `PROMOTE_CONTEXTS`;
2. 60 is a soft score, above the 0 an unresolvable option gets, so it is a
   demotion and not a ban;
3. the basis pool counts the **active's** name, so Piotr's exact trigger — 0
   benched Pokemon **and** 0 basics in hand — is not a condition anywhere in
   the codebase.

The `DISCARD_CONTEXTS` mirror is the unguarded half: `-card_usefulness(card.id)`
is basis-blind, so a live basic can be pitched over a dead evolution.

**The shipped neural agent has no coverage at all.** `apply_play_overrides`
returns early on any non-MAIN context (`rl/plan.py:690`), so every search
submenu — `TO_HAND`, `LOOK`, the promote prompts — is raw argmax over net
logits with no rule and no feature describing basis availability.

Worth stating plainly: **this defect is inert on the current ship.**
`submission/deck.csv` is the Ogerpon list, 4x Teal Mask Ogerpon ex and zero
evolutions. It bites on the Alakazam / lucario / dragapult-class decks in
`decks/`, which is where it has to be measured.

### Found, recorded, not fixed: the option target-resolution bug

`rl/encoders.py:207` and `:717` resolve an option's `inPlayArea` /
`inPlayIndex` target against `your_index` rather than `opt.playerIndex`:

    tgt = _card_id_at(state, opt.inPlayArea, opt.inPlayIndex, your_index)

Correct for ATTACH / EVOLVE / tool attachment, which only ever address our own
board. Any option that addresses the **opponent's** board through `inPlayArea`
encodes *our* Pokemon at that index into columns 53-88 instead. Fixing it would
move columns inside every trained width — a silent live policy change — so
Phase 1 carries a counter that settles whether it is a live defect or a
theoretical one, and the fix, if warranted, is a separate ship.

### Scope, agreed with Piotr before any code

Probes + rule-pilot fixes + neural capability. **No collect, no train, no
ship.** Turning `scaling=True` on for `enumerate_plans`, the race block, the
threat model and the solver teacher remains the next bet — it changes what the
TEACHER believes and cannot be evaluated without a fresh corpus.

The order is measure-then-fix, and it is not stylistic. Four instruments in M41
read flat-damage semantics and produced a confident wrong answer; three levers
were killed by their own mechanism probes before a gate cell was spent. Every
ladder in Phase 1 must be able to kill its own fix.

### Two kills, before a line of pilot code was written

**`retreat_stranded` is not a defect.** 33 + 156 situations across the two rule
decks, and **zero** missed fixes. The plan pre-committed to scoping the
retreat-cost rule off this number — "if the ladder reads zero, record that and
do not add a rule" — so Phase 4's retreat item is **dropped**. Retreat cost
stays unread by both pilots, on evidence.

That reading only exists because the first version of the ladder was wrong. It
reported **45.0% (9 of 20)** and then **183.3% (11 of 6)** — a rate above 100%,
which is what exposed it: rungs 2 and 3 were independent `if`s, so ending a turn
stranded with *no legal way out* counted as a miss. Gating rung 3 on rung 2 took
the same board states from "45% defect" to "0%". Fifth instrument in two
milestones to read a real board and return a confident wrong answer, and the
only reason it was caught is that the bug happened to produce an impossible
number rather than a plausible one.

**`wasted_stadium` was RULE-IMPOSSIBLE and had to be thrown away.** The original
framing — "we replaced the stadium in play with the same card" — read 0 on all
three pairings. Rather than record that as a clean pilot, measured it directly:
over 20 prompts where a stadium was out **and** a stadium PLAY was offered,
same-id offers **0**, different-id offers **20**. The engine enforces the real
same-name Stadium rule, so the ladder could only ever read 0 and would have
credited any "fix" for a defect the rules already prevent. `same_id_offered`
survives as a counter so the void framing cannot be re-proposed from a clean
slate.

### `stadium_ignored` — the replacement ladder, and the only defect that touches the LIVE ship

Re-framed to something the pilot can actually get wrong: a stadium PLAY is on
the menu, a **different** stadium is already in play (so playing ours removes
theirs), and we decline anyway.

    alakazam rule      41 / 48   85.4%   all 41 vs Spikemuth Gym
    lucario_evolved    46 / 53   86.8%   all 46 vs Festival Grounds
    ogerpon SHIP       42 / 65   64.6%   all 42 vs Spikemuth Gym

Two things make this the headline. First, it is the **only ladder that fires on
the shipped agent** — the other four are structurally zero on the Ogerpon deck,
exactly as the Phase 0 review predicted (no evolutions, and Ogerpon is an
own-energy scaler so `energy_is_dead` can never be true for it). Second,
Festival Grounds is not a neutral stadium: it is what lets Dipplin attack
**twice** per turn (`rl/scaling.py`, the 08-03 archetype read). Declining to
displace it 86.8% of the time is handing the Dipplin line its whole engine.

The Phase 0 review said stadium **visibility** was not the gap, and that holds —
the net sees the stadium's full 36-column identity. What this measures is the
other half of that same finding: nothing consumes it. `tcg/pilot.py` mentions
`state.stadium` exactly once, as a zone in `card_at`'s dict.

### `over_attach` is a NEURAL defect, not a rule-pilot one

## 2026-08-04 — CORRECTION: the stadium number was a per-prompt artifact, and the live ship is clean

The entry above reported `stadium_ignored` at 85.4% / 86.8% / **64.6%** and
called it "the only ladder that fires on the shipped agent". **That was wrong,
and the instrument was wrong in the way this milestone exists to catch.**

Caught by cross-checking the new `[stadium-ignored]` post-mortem flag against
the probe. The flag read **zero** on the M41 Ogerpon QC replays while the probe
read 58.5% on the same deck. One of them had to be broken, so I read the
replays directly rather than picking the number I preferred:

    ep_g000_a0.json  turns with the option: [7, 11]   played on: [7, 11]
    ep_g002_a0.json  turns with the option: [5, 11]   played on: [5, 11]

The ship played its stadium on **every turn the option existed**, 4 for 4. The
flag was right; the probe was counting per PROMPT. A turn holds many MAIN
prompts, so playing the stadium at prompt 5 left prompts 1-4 recorded as
declines — inflating the rate by roughly 5x. `rl/postmortem.py:250` had already
committed to the correct semantics four milestones ago: *"fixing it later in
the same turn is fine; ending the turn in the bad state is the failure."* The
probe simply did not inherit it.

### Corrected, per TURN

| pairing | turns with a stadium PLAY offered | ...theirs in play | ...turn ENDED with theirs out | was |
|---|---|---|---|---|
| alakazam rule vs grim | 21 | 10 | **1 (10.0%)** | 87.5% |
| lucario_evolved vs festival | 18 | 16 | **10 (62.5%)** | 96.6% |
| **ogerpon SHIP** vs grim | 32 | 23 | **0 (0.0%)** | 64.6% |

**The live ship is clean on stadiums.** So is the alakazam rule pilot, near
enough. The defect is real on exactly one pairing — `lucario_evolved` against
Festival Grounds, at 62.5% — and that one still matters, because Festival
Grounds is what lets the Dipplin line attack twice per turn. But it is one
pairing, not a universal blind spot, and the claim that it touches the shipped
agent is withdrawn.

Sixth instrument in two milestones to read a real board and return a confident
wrong answer, and the second in this milestone alone. The pattern in both M42
cases is the same: **the rung semantics, not the predicate.** `retreat_stranded`
counted misses the pilot had no legal way to avoid; `stadium_ignored` counted
prompts where the pilot had not yet acted but would. Neither predicate was
wrong about the board.

The only reason both were caught is that each produced something impossible to
ignore — a rate above 100%, and a flat contradiction between two instruments
measuring the same thing. That is an argument for building the post-mortem flag
and the probe as independent implementations rather than sharing code between
them: they disagree loudly, where a shared helper would have been silently
wrong twice.

KEEP+PROMOTE (36 of 47 measured misses were invisible to the old scope) and it
