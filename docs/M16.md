### THE finding: option-identity blindness (since v1, never diagnosed)

- **PLAY options carry only a hand index** (no `area`, no `cardId`) →
  `encode_option`/`encode_option_v2` never resolve WHICH card is played:
  zero card features, embedding id 0. "Play Boss's Orders" ≡ "play Poké Pad"
  — byte-identical option vectors, choice decided by tie-break noise.
  **431/1353 live decision states (~14/game, 32%) offered ≥2 distinct
  trainers the net could not tell apart.**
- **ATTACK options never encode `attackId`** → same-Pokémon attacks alias
  (~3 blind attack choices/game; argsort tie-break picks by option order).
  NUMBER options (`opt.number`) unencoded too.
- Teacher-side proof: **all 5,628 PLAY labels in plan_m15 have acted-id 0**
  — the card identity was discarded AT COLLECTION. Existing shards cannot
  teach trainer choice even in principle → re-collection required.
- Precedent: the M1 Stage-B fix treated exactly this aliasing for ATTACH
  targets ("attach to Mega Lucario" ≡ "attach to a benchwarmer", 337/500
  menus aliased). PLAY/ATTACK were the untreated half of the menu.
- Downstream symptoms it explains: Boss's Orders 0.35 plays/game (buddy's
  gust discipline ~core of its 0.615); Lunatone ability usage halved
  (1.0/game vs plan2 2.2); trainer usage tracking hand frequency rather
  than value.

## 2026-07-18 — the M16 change: option-identity encoding (v3o)

Design (implemented before the pipeline run; measurement decides):

- `encode_option_v2` (rl + tcg twins, submission copy synced): resolves
  PLAY card id from `hand[opt.index]` → fills the existing acted-card FEAT
  block + embedding id; appends `N_OPTION_EXTRA = 4` identity features:
  `[atk printed dmg/300, atk cost/5, atk effective dmg vs opp active/300,
  number/10]` (weakness/resistance/CONDITIONAL_ATTACKS-aware, math mirrors
  `_charged_best`). `OPTION_V3_DIM = OPTION_DIM + 4`. v1 `encode_option`
  stays byte-identical.
- `encode_option_v2_legacy` (both twins) = exact pre-M16 encoding;
  matchrunner selects encoder by sniffed checkpoint width so pinned
  baselines (plan0c 0.357, v3h_plan1 0.384, osv2_*) stay reproducible.
- `OptionScorerV3(option_dim=...)` both twins (the M15 `n_state_ids`
  precedent); `option_dim_of(sd)` sniffing in rl/policy.py; loaders updated
  (matchrunner, plan_iter workers/train, rank, setup_value, shipping).
- `load_v3h_into_v3o` migration: option_enc.0 new numeric columns
  ZERO-init, embedding column block shifted — v3o(legacy-encoded options)
  == old net exactly (warm-start invariant, 4th use). `--init-v3o` flag.
  NB live PLAY ids light up already-trained embedding rows — intended
  head start, not identity.
- Options pad shim in BCDatasetV3 (legacy shards' blank PLAY block ==
  "no identity info", same semantics as the M15 state_ids shim).

Pipeline intent: re-collect ~800 games (fixed encoder, mixed opponents,
<2h rule) → train `osv3o_plan1` warm-start from osv3h_plan1 → measure per
measure-agent protocol → ship per observation-run policy.
