# M7 — The Deck Factory Loop: implementation diary

**Status:** 🚧 Active (started 2026-07-09). Spec: [M7-plan.md](M7-plan.md).

## Why

M0–M6's measured conclusion (DECISIONS.md): the #1 bottleneck is opponent-field
diversity — every offline search overfits to 2 rule pilots + bc_v1 while the real field
is ~4,500 teams. M7.0 attacks it first because it's cheap, independent, and changes the
category of every downstream problem: Kaggle serializes both agents' actions per episode,
and the env contract makes each agent's *first* action its 60-card decklist — so our own
submissions' replays carry real opponent decks.

## Assumptions (tracked)

All three are schema bets that only the [NET] spike (runbook below) can settle — this
sandbox has no Kaggle network access, so M7.0 landed as offline infrastructure + tests.

|---|---|---|---|

| 2 | Endpoint reachable: `EpisodeService/{ListEpisodes,GetEpisodeReplay}` works for this competition (fallback: kaggle CLI + `import-file`) | `python -m rl.kaggle_ingest list --sub 54474043` | ⏳ [NET] |

Go/no-go (M7-plan §7): decklists extractable → full plan; only outcomes → keep
forensics, drop the meta-field/BC edges, recalibrate gates to the old anchor field.

## Design (M7.0 — `rl/kaggle_ingest.py`)

- **Fetch/parse seam.** `fetch_episode`/`list_episodes` are the only network
  touchpoints (lazy `requests`, injectable fetchers); everything downstream is pure and
  replays the immutable gzip cache `data/kaggle/raw/episode_<id>.json.gz` (atomic
  writes, ~1 req/s throttle, resumable). Parser fixes reprocess history for free.
- **Two payload shapes** accepted: `env.toJSON()` dicts and the `GetEpisodeReplay`
  `{"replay": "<json-string>"}` wrapper. `parse_episode` is schema-*tolerant*
  (missing decks/rewards → warnings, never crashes); the HARD asserts live in the
  `verify` command, because discovering the schema is the milestone.
- **`deck_hash`** = sha1 of sorted ids — the deck identity the M7.2 league imports.
- **Archetypes**: exact hash, then greedy agglomerative cosine (≥0.95) over the
  L2-normalized pooled FEAT of the Pokémon core (the representation the 98% probe
  validated). Deterministic ordering → stable labels across reruns. The FEAT matrix is
  re-derived from `cards_features.parquet` rather than imported from `rl/encoders.py`
  (encoders → `rl.combat` → `cg`; ingestion must run engine-free). Tech debt: extract a
  shared cg-free `rl/features.py` during the M7.3 encoders-v2 work.
- **Outputs**: `data/kaggle/episodes.parquet` (outcomes + schema evidence per episode),
  `data/kaggle/opp_decks.parquet` (per-seat decks + archetypes), frozen
  `data/kaggle/meta_v<N>/` snapshots (validated deck csvs + manifest), and
  `build_meta_field` → `("generic", deck_csv_path)` specs matching the collector's
  picklable-tuple convention (the M7.2 matchrunner resolves name-or-path).
- **Honest scoping**: `bc_shards_from_opponents` is an *audit* only (encoding needs a
  confirmed obs schema + the engine); `forensics` defers first-KO for the same reason.

## Design (M7.1 — `rl/deck_build.py` + `field_fitness`)

Two data facts unlock an engine-free factory (both pinned in tests):

1. **Evolution is by NAME, not card id.** `evolves_from_id` points at one specific
   printing, but decks legally play any same-named card — the tuned Lucario deck runs
   Riolu #677 (80 HP) while Mega Lucario ex's `evolves_from_id` is Riolu #974 (70 HP).
   Lines are walked by name, taking the highest-HP printing of each pre-evolution.
2. **`attackId` ↔ card via cumulative `n_attacks`** in card_id order (the parquets were
   written in one pass; verified: all 1,556 attacks assign with zero `max_damage`
   mismatches). This gives per-attack damage AND cost without the engine —
   `min_attack_cost` alone is the *cheapest* attack, the wrong denominator for
   damage-per-energy (Mega Lucario: min cost 1 = Aura Jab 130, best = Mega Brave 270/2).

Pipeline: `enumerate_lines()` (complete basic→final chains, 1–3 stages) →
`score_line` = damage-per-energy × weakness-coverage − prize-liability − setup-cost
(setup penalty strong on purpose: M6's floor-test weakness is slow setups; variable
attacks discounted 0.5 — printed damage is best-case) → shells v1 mined from the known
decks (`data/shells.json`; `harvested_shell()` is the §2.3 source-3 hook, live after
the [NET] spike) → `build_deck` (4-3 / 4-3-2 line counts, 10–14 matched basics by
best-attack cost, dual-type split gives a coverage tech 4 basics, shell fills, energy
pads — legal by construction, asserted) → `generate` round-robins the top-K lines ×
shells × {no-tech, coverage-tech}, deduped by `deck_hash`, into `decks/gen/` + manifest.

`rl/deck_search.field_fitness(deck, field, games_per_opp, pilot)` rates candidates
vs the diverse FIXED anchor field, never mirror-only (the documented mirror-overfit
failure). `OpponentSpec` tuples now cover rule/model/generic/random with name-, path-,
or ids-valued decks; the battle loops graduate to `rl/matchrunner.py` in M7.2.

First batch (pool-histogram meta, since ingestion hasn't run): 40 legal candidates
across 10 archetypes — top lines Ceruledge, Palafin ex, Decidueye, Greninja ex,
Medicham; Mega Lucario ex ranks lower under the strong setup/prize penalties (270 dmg
but cost 2 + 3-prize liability).

## Design (M7.2 — `rl/league.py` + `rl/matchrunner.py`)

**Match runner** (`rl/matchrunner.py`) is now the canonical home of the
`OpponentSpec` vocabulary and the slot-fair direct-engine battle loop —
`deck_search.matchup`/`_play_vs_spec`/`_spec_pilot`/`_resolve_deck` are thin
delegating wrappers (signatures unchanged), the collector migrates in M7.3
together with per-game deck sampling (it layers tensor recording on top of
match running), and `eval.play_games` stays on kaggle_environments because it
exercises the SHIPPED file agents. Parallelism follows the collector pattern:
spawn Pool over even-sized game chunks (~2 jobs/worker, only str/int tuples
pickled); `workers<=1` runs in-process, which is also the injected-`game_fn`
test seam. `_engine_game` optionally accumulates per-seat moves/time/errors —
the G1/G6 gate inputs come from the same games as G2–G4, no second pass.

**League** (`rl/league.py`, persisted at `data/league/league.json`): a
PlackettLuce table over (deck, pilot) entries. Decisions worth recording:

- **Frozen ≠ fixed rating.** Anchors are permanent members excluded from
  candidate scheduling/promotion, but their *ratings* update — the self-test
  needs anchors rated among themselves; the scale is pinned by the population
  being permanent, not by freezing mu.
- **Draws** skip the rating update (the `rate_population` convention) but count
  toward `games` and as half a win in win rates (the `field_fitness` convention).
- **Specs are normalized on add**: every entry's deck slot is rewritten to its
  registered `data/league/decks/<hash>.csv`, so league.json round-trips cleanly
  (JSON lists → tuples on load) and specs stay hashable.
- **Gates are data**: `gate --entry <id>` writes
  `data/league/gates/<entry>.json` — per-gate `{threshold, n, value, pass,
  date}` plus the field version and `n_scale` (smoke runs are honestly
  labeled). G5's fixed reference opponent (`generic+lucario`) is recorded in
  the file. Ship-eligibility (`ship_eligible`) is pure arithmetic; the `rl.gate`
  bundle suite stays a separate manual step.
- **Scheduling**: candidates play every anchor (40 games each) until their
  anchor schedule is done, then their 3 nearest-ordinal peers. Interrupted runs
  may replay some anchor games — extra n only sharpens ratings.

## Design (M7.2b — race-math lookahead L1)

The deck-agnostic port of the experts' planning edge, targeting M6's measured
floor-test failure (the pilot self-decks won games: ~1 KO/turn while milling).
Key discovery: the Lucario expert's `AttackPlan` is a *single-turn* attack
commitment — its multi-turn behavior emerges from per-turn re-commitment plus
energy banking. So L1 ports **race math**, not a plan object:

- **Primitives** (`rl/combat.py` ↔ `tcg/combat.py`, pure Python — both files
  ship verbatim in the rule bundle): `charged_best` (best attack at FULL charge;
  `best_damage`'s affordable-only view is why the pilot stopped charging once
  the *cheapest* attack was paid), `turns_to_ready` (total-cost energy gap,
  attach-1/turn), `hits_to_ko`, and `turns_to_first_ko = max(gap,1) + hits − 1`
  (an attacker one energy short fires THIS turn — the same semantics as the
  pinned 4000 unblock tier). `UNREACHABLE(_TURNS) = 99` sentinel.
- **Scorer rewiring** (both pilots + `tcg/constants.py`, lockstep for parity):
  attach now bonuses my fastest closer (2750 active / 2680 bench — the bench
  closer deliberately outranks the KO tier: the attach doesn't end the turn, the
  KO fires on re-prompt); "already loaded" means the BEST attack is charged;
  promote subtracts 50 per attach still needed (capped ×4); and **close mode**:
  when the opponent board is harmless (every Pokémon known + zero printed
  damage), chip attacks jump above trainers (2300+) so the pilot attacks every
  turn instead of milling. Close mode v1 is deliberately conservative — it's
  exactly the floor case and (almost) never fires vs a real opponent, so the
  >30% expert gate can't regress through it; the full prize-race comparison is
  deferred.
- **Floor deck committed**: `decks/floor_zero_damage.csv` (4× the highest-HP
  zero-damage basics + energy; `python -m rl.deck_build floor` regenerates it) —
  M6's ad-hoc floor measurement is now reproducible.
- **Deferred**: k-turn `encode_state` features land in encoders-v2 (M7.3) — v1
  must stay byte-identical (bc_v1/value artifacts + shipped-npz parity, risk 4).

## M7.1 gate runbook ([ENGINE] — needs `cg/libcg.so`)

```bash
uv run python -m rl.deck_build generate --n 40          # regenerate with --meta after M7.0
uv run python - <<'PY'
from rl.deck_search import field_fitness, matchup, _resolve_deck
import json, pathlib
gen = pathlib.Path("decks/gen")
anchor_field = [("rule", "lucario", "lucario"), ("rule", "iono", "iono"),
                ("generic", "lucario"), ("generic", "iono"), ("random", "kyogre")]
scores = {}
for entry in json.load(open(gen / "manifest.json"))["decks"]:
    deck = _resolve_deck(str(gen / entry["csv"]))
    wr, per_opp = field_fitness(deck, anchor_field, games_per_opp=60)
    scores[entry["csv"]] = (wr, entry["line"])
    print(f"{entry['line']:<24} {wr:.3f}")
# GATE 1: best candidate >= 50% vs the Lucario deck, same generic pilot, n=400
best = max(scores, key=lambda k: scores[k][0])
r = field_fitness(_resolve_deck(str(gen / best)), [("generic", "lucario")],
                  games_per_opp=400)[0]
print(f"gate 1 (>=0.50 vs lucario deck, n=400): {r:.3f}", "PASS" if r >= .5 else "FAIL")
# GATE 2: >=3 distinct archetypes above the anchor-field median
import statistics
med = statistics.median(wr for wr, _ in scores.values())
above = {line for wr, line in scores.values() if wr > med}
print(f"gate 2 (>=3 archetypes above median {med:.3f}):", len(above), sorted(above))
PY
```

Record both gate numbers in the results log; feed the top decks to `rl.league add`
once M7.2 lands. After the [NET] spike, rerun `generate` with
`--meta data/kaggle/opp_decks.parquet` and re-gate — promotions must hold on the

## M7.2 runbook ([ENGINE] — needs `cg/libcg.so`)

```bash
# 0. Cross-check the fast path vs the shipped-agent path (verification item 5):
#    expect generic-vs-random ~95%, and remember slot 0 alone carries ~61%.
uv run python -m rl.matchrunner play --a generic:lucario --b random:kyogre -n 200 --workers 4

# 1. The M7.2 gate: anchors must reproduce the M6 ordering
#    (lucario_expert ≈ tuned > generic+lucario > bc_v1+kyogre > random+kyogre;
#    expert-vs-tuned is a statistical tie — the check is soft there).
uv run python -m rl.league selftest --games 40 --workers 4

# 2. Rate the M7.1 candidates (league.json ships pre-initialized with the anchors;
#    add-batch is shell-loop-free, so it works in PowerShell too):
uv run python -m rl.league add-batch --dir decks/gen
uv run python -m rl.league run --games-per-anchor 40 --workers 4     # ~13 min at 50k games/hr
uv run python -m rl.league standings

# 3. Gate smoke on an anchor (full n later, on real candidates):
uv run python -m rl.league gate --entry generic+lucario --n-scale 0.25

# 4. Promote the best generated deck (also the M7.1 gate, now league-official):
uv run python -m rl.league promote --deck decks/gen/deck_<best>.csv
```

Record the selftest verdict + final standings here; if the ordering fails,
that's a DECISIONS.md entry (it would mean the M6 measurements don't replicate
