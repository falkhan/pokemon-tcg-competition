# M3 — Combat-Lookahead Features → a Strong *Trained* Lucario Pilot

**Status:** 🚧 Active (started 2026-07-08)
**Plan:** `.claude/plans/…` (approved) · **Findings log:** [DECISIONS.md](DECISIONS.md)

## Why this milestone

M2 hit an honest wall: our champion is still `bc_v1` on the *weak* Kyogre deck, and it loses
to the rule experts. We ruled out (with evidence) PPO and inference-time MCTS as ways to beat
a strong BC policy here. The one lever left that we *diagnosed but never pulled*:

> Behavior cloning failed on the Lucario expert (55% fidelity → a weaker agent) because the
> expert's edge is **combat lookahead** it computes internally (the `AttackPlan`). But that
> lookahead is **computable from the card database**, not truly hidden. If we compute those
> tactical quantities and feed them to the network, the expert's decisions become a near-
> deterministic function of features the net can *see* — so BC fidelity should jump.

Goal: a **trained** (not copied) strong pilot on the **strong** Lucario deck — a base worth
building on, and finally an agent that beats bc_v1+Kyogre.

## The combat features (11), from the expert's `AttackPlan`

Computed in `rl/encoders.py` (`_combat_features`), from `cg.api` attack/card tables:
`my max damage`, `opp max damage`, `I can KO opp active`, `opp can KO me`,
`one energy from a KO`, `my active can attack`, `prize race`, `opp active prize value`,
`# of my ready attackers`, `my active hp%`, `opp active hp%`.
Damage math mirrors the expert: affordable-attack check (colorless = any), ×2 on weakness /
−30 on resistance vs the attacker's type. STATE_DIM 1206 → 1217.

  damage must be parsed from `Attack.text_` (a real but Lucario-irrelevant gap).

## Verdict: M3 refuted

Assumption 1 (expert decisions ≈ computable combat features → higher fidelity) is **false** on
both metrics. Why: (a) the combat features are *state-level aggregates* but the expert's fine
decisions (which attack/target, setup order) need per-option detail; (b) the ~56% fidelity
ceiling is structural — ~67% of menus contain interchangeable/aliased options (M1), so
index-accuracy can't climb much regardless of features; (c) more deeply, **BC of the Lucario
expert is fundamentally weak** (our clones win only 25–38% vs bc_v1+Kyogre) — the strong deck
doesn't help if we can't pilot it.

**bc_v1 + Kyogre remains champion.** Every neural approach tried (BC on Kyogre/Lucario ±combat
features, PPO, MCTS, supervised-value+search) fails to beat it, and it loses to the rule
experts. See docs/M2.md + DECISIONS.md for the full map. Next decision is strategic, not another
tweak — recorded in DECISIONS.

## Known gaps

- Variable-damage attacks (`×…`) report engine `damage=0` → `_best_damage` understates them.
- Single-turn features won't capture the expert's multi-turn planning — may reach "strong",
  not "matches expert." A strong base is the goal.
