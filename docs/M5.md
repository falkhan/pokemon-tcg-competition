# M5 — Win Bigly: domain-engineered agent, leaderboard as fitness

**Status:** 🚧 Active (started 2026-07-08)

## Why / the strategy

M1–M4 proved it comprehensively: on a CPU budget, **hand-engineered rule agents with tuned
decks beat everything we train** (bc_v1 = 640 vs ~1100+ at the top; the Lucario rule agent
beats bc_v1 ~86%). And we **can't simulate the real 4,500-team meta** — our offline field is
just 2 rule pilots + bc_v1, which every search overfits to (deck search, PPO, all mirror-overfit).

Two conclusions drive M5:
1. **Build on a strong rule agent** (the Lucario agent is our strongest asset), and make it
   genuinely ours + stronger by **optimizing it** — not copying it verbatim.
2. **The leaderboard IS our fitness function.** We can't simulate the meta, but we can submit
   and read the score. So M5 is a submit → measure → improve loop against the real field.

This keeps our ML/RL tooling central as the *measurement + optimization* layer (self-play eval,
parameter search), while the agent itself is rule-based where that's what wins.

## Approach

- **Foundation:** the Lucario rule agent (`sample-agent/main.py`) + its tuned deck.
- **Make it ours + stronger — heuristic parameter optimization:** the agent is full of hardcoded
  magic numbers (attack scores, energy_score weights, target priorities, the −500/+220/+300
  biases…). Expose them as a parameter vector and optimize via self-play (hill-climb / CMA-ES),
  fitness vs a diverse fixed field (Iono + bc_v1 + past variants). This is black-box optimization
  of a rule agent — ML-central, our contribution, genuinely different from the sample.
- **Leaderboard loop:** package the best agent, submit, read the score, iterate. Each submission
  is a real data point against the meta we can't simulate.

## Milestones

- **M5.0** — packaging: build/submit a *rule-agent-based* submission (main.py + cg + deck).
  Establish where our strongest current asset actually lands on the board (the real baseline).
- **M5.1** — expose the Lucario agent's heuristic magic-numbers as a parameter vector.
- **M5.2** — self-play parameter optimization (diverse-field fitness, anti-overfit); gate: tuned
  agent beats the stock Lucario agent ≥55% slot-fair AND holds up vs Iono/bc_v1.
- **M5.3** — submit the tuned agent; read leaderboard delta vs the stock-Lucario baseline. Iterate.
- **M5.4** — (stretch) deck + heuristics co-optimization; or the value-head/MCTS refinement on
  top of the strong rule priors (the one search setup we haven't tried with strong priors).

## Risks

- Heuristic params may be near-optimal already (hand-tuned) → small gains.
- Offline diverse-field fitness still overfits vs the real meta → the leaderboard loop is the
  real check, but daily submission limits make iterations expensive; make each count.
- "Rule agent + optimized params/deck" is a hybrid, intentionally — RL/ML is the optimization
  and measurement layer, not the pilot.

## Results log

- **M5.1 ✅** parameterized the Lucario agent's 5 top weights (`sample-agent-tuned/`, overridable
  via `weights.json` or in-process). Parity: tuned(default) ≈ stock (45% @ n=40, noise);
  tuned(zeroed) 30% (weights matter). Loader: `rl.teacher.load_teacher(agent="tuned", weights=…)`.
- **M5.2 ❌** self-play weight tuning (fitness vs Iono + stock-Lucario): **0/20** proposals beat
  the defaults (0.680). The agent's heuristics are already tuned — same verdict as M4 deck search.
- **Strategic wall confirmed 3× over:** neural (M1–M3), deck (M4), heuristics (M5) all find the
  provided rule agent is near-optimal for the *simulable* field and can't be improved offline.
  The only remaining lever is the **real leaderboard** — which requires shipping a strong probe.
- **M5-hybrid ❌** rule agent + neural value-head 1-ply override (value net retrained to 0.92
  sign-acc on the 1217-dim encoder). Loses to the stock rule agent at every margin
  (0.10→32%, 0.20→46%, 0.35→32%). The value head can classify win/loss but can't *rank* actions
  via 1-ply-on-determinized-states well enough to improve a strong pilot — same failure as MCTS
  and 1-ply lookahead earlier. `rl/hybrid.py`, `checkpoints/hybrid_value.pt`.
- M5.3 leaderboard delta: _(pending a ship decision — see verdict)_

## Verdict

Every avenue to beat OR improve the rule agent has now failed: neural pilots (M1–M3), deck
search (M4), heuristic tuning (M5.2), and the value-head hybrid (M5-hybrid). The provided rule
agent is a hard ceiling for our toolset on this budget. The only remaining lever is the real
leaderboard, which requires shipping the rule agent (strongest, but ≈ the sample) or accepting
bc_v1 (ours, 640). This is now a pure strategy choice, not an engineering one.
