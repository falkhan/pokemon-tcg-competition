## Plan

### Context — M17 root cause corrected

The M17 postmortem's measurements all verify against the raw artifacts (recomputed with the
0=WIN jsonl decoding; no inversions), but its root-cause hypothesis ("the new value net is
mis-calibrated") is wrong. **The SETUP=0 collapse was a code bug:**

- `leaf_value` (`rl/plan_iter.py:73`) hard-codes `encode_state_v2` (12 state-ids).
- The M17 value net `osv3o_setupval1.pt` is hand-aware: 20 ids (`state_enc.0` in-width 1708);
  it received 1580-wide input → `RuntimeError` on **every** call.
- The bare `except Exception: pass` (`rl/plan_iter.py:99-100`) swallowed it silently →
  `value_solve` always returned `(None, None)` → SETUP=0 across all 10k games.
- The net was never evaluated once. The 10k collection was plain expert imitation at high
  volume, diluting M16's signal — that dilution is the real cause of the plan2 regression
  (mirror 0.380, meta 0.396, h2h 0.400 vs plan1).
- The correct encoder-dispatch pattern already existed at `rl/plan_iter.py:342-345`; nobody
  applied it to `leaf_value` when the value net went hand-aware.

Supporting pre-measurement for M18a: `osv3o_plan1` disagrees with the stored solver labels on
**23.5%** of plan_m16 rows (589/2502, shard w00_0000) and **15.7%** of plan_m17b rows
(1169/7448) — ample re-weighting signal.

### Stages

- **T0 — code (one pass, before any worker spawns):** (1) `leaf_value` encoder dispatch on
  `vnet.n_state_ids`; (2) replace the silent swallow with `vs_calls`/`vs_errors` counters +
  one-time traceback, record score-vs-leaf margins, `--vs-margin` CLI flag, aggregate
  `value-solve:` summary line + loud `WARNING: SETUP=0`; (3) optional `weights` shard column
  through BCDatasetV3 / collate_v3 / weighted policy-CE (value huber + plan CE + val_acc stay
  unweighted → comparable); (4) new `relabel` subcommand (batched student argmax vs stored
  labels, writes sibling `_w` dirs, W=10 on disagreement); (5) ei-mode disagreement weights
  recorded at collection (fallback path); (6) regression tests for all of the above.
- **T1 — sanity gate (~15 min):** 60-game expert collect with `osv3o_setupval1`. Gate:
  `vs_errors==0` and SETUP ≥ 30 (M16 ran ~3/game). SETUP=0 with no errors → recalibrate
  `--vs-margin ≈ max(50, p80)` from the printed margin distribution and re-run; degenerate
  distribution (p99 ≤ 0) → fall back to old net `osv3_setupval2` for T2.
- **T2 — M18b collect (~45-75 min):** 800 games, M16 flags, seed 2 → `data/plan_m18`.
- **T3 — M18a (concurrent with T2):** relabel plan_m16+plan_m15 with plan1 W=10 → train
  `osv3o_plan4` on the `_w` dirs, `--init osv3o_plan1` (NOT `--init-v3o`), 5ep 1e-4 bs256.
- **T4 — M18b train:** `osv3o_plan3` on `data/plan_m18 data/plan_m16`, same recipe.
  plan_m17/plan_m17b excluded (the proven diluent).
- **T5 — gate ladder per candidate:** screen n=400 seed1 (kill < 0.40) → confirm seed2
  pooled n=800 (> 0.424) → meta co-gate (> 0.534) → floors → if both candidates pass, h2h
  n=400 and ship the higher pooled mirror via `./build_submission.sh --checkpoint <winner>.pt`.
- Hermes/Telegram: update at every stage transition, hourly heartbeat on runs > 30 min,
  immediate notification on failures/kills (hard rule, now in CLAUDE.md).

Candidate names: `osv3o_plan3` = M18b, `osv3o_plan4` = M18a-A1, `osv3o_plan5` reserved
(A2: plan_m17b disagreement-heavy rows — only if plan4 screens 0.40-0.424).

### Risks

- Weighted `train_loss` not comparable across milestones (val_acc/plan_acc still are).
- Offline relabel = weighted BC-repair on the solver's state distribution (teacher's committed
  plan as conditioning) — weaker than true DAgger; fallback = ei-mode online collection with
  the new weights column.
- EI/DAgger measured dead in M9/M11 — but pre-option-identity; cheap first pass justified.
- SETUP still 0 after fix → caught at T1 before large spend; last resort = old value net.
