# M6 — The Real Pivot: build strong decks + a deck-agnostic pilot

**Status:** 🚧 Active (started 2026-07-08). Plan: `.claude/plans/…` (approved).

## Why

M1–M5 proved the *public* Lucario sample agent is the ceiling of what we can build or improve,
and shipping it gains nothing (everyone starts there). The two things we've never done are the
actual levers to win: **(1) build genuinely strong decks** from the 1,267-card pool (synergy +
consistency + tech, not random), and **(2) pilot any deck** with general logic. Every prior
milestone was bottlenecked by only having *card-specific* pilots — so we could never test a new
deck. **The unlock is a deck-agnostic pilot** (built on M3's `_best_damage`/combat core); then we
build & search decks with it, and use the real leaderboard as the fitness function.

## Assumptions (tracked)

| # | Assumption | Test | Status |
|---|---|---|---|
| 1 | A general rule pilot can play any deck competently (combat-feature driven) | ≥ ~80% vs random, ≥40% vs Lucario agent | ⏳ |
| 2 | Deck quality (weakness-aware synergy) beats pilot skill | best self-built deck > Lucario deck ≥55% (same pilot) | ⏳ |
| 3 | Generic-pilot + strong-deck generalises to the real field | leaderboard > bc_v1's 640 | ⏳ |

## Design

- **Generic pilot** (`rl/generic_pilot.py`): scores every option by general principles + M3 combat.
  Tiers: beneficial free setup (ability/evolve/attach-to-attacker/play/useful-trainer) **above**
  the turn-ending ATTACK, above marginal setup, above END — with two lookaheads: attach/retreat
  that *unblocks a lethal this turn* jumps to the top. Card-selection contexts (SETUP/SWITCH/
  TO_HAND/DISCARD/…) scored by `score_card` (promote best attacker / fetch useful / discard worst)
  — **not** the dumb "pick first" fallback.
- **Deck builder** (`rl/deck_build.py`, next): strong attacker cores (weakness-aware — Fire/
  Fighting/Lightning hit 220/188/155 of the pool) + proven consistency shell + type-matched energy.
- **Deck search** (reuse `rl/deck_search.py`): diverse-field hill-climb under the generic pilot.
- **Ship loop:** rule-based submission (main.py + cg + deck), submit, read score, iterate.

## Results log

- **M6.0 skeleton ✅** — priority-only pilot plays full legal games.
- **M6.0 scorers (attack/attach/play/retreat)**: vs random **75%**, vs Lucario **32%**. Diagnosis:
  MAIN was handled (565 decisions) but ~350 card-selection decisions (TO_HAND 103, SWITCH 62,
  DISCARD 45, SETUP_ACTIVE 15, …) fell through to the dumb "pick-first" fallback — arbitrary
  starters, promotions, and fetches.
- **M6.0 + `score_card`**: vs random **80%** (near the deck's ~88% ceiling), vs Lucario **30%**.
  score_card made the pilot consistent (fixed the coin-flip selections) but it's still well behind
  the card-specific expert.
- **M6.0 legibility check ❌ (the blocker):** generic-pilot **Lucario vs Iono = 48%** — but
  *expert* pilots give Lucario **76%**. The generic pilot **washes out deck strength**: it pilots
  both decks mediocrely (doesn't execute the evolution line + energy concentration that makes
  Lucario strong), so strong and weak decks look identical. → An evaluator this weak can't drive
  deck search (M6.2).
- **Root-cause chase (3 tests):**
  1. The 48% was *ambiguous* — "expert 76%" blends deck strength + pilot skill; same-pilot 48%
     could mean "pilot washout" OR "Lucario≈Iono decks are genuinely close."
  2. **good-vs-weak** (generic pilot, Lucario deck vs a functional mono-Fighting aggro deck of
     20–40dmg single-prize basics) = **57%** — but that's a legit aggro-vs-slow-ex margin, so
     inconclusive. (Confirmed the pilot DOES evolve to Mega Lucario ex and load its 2-energy /
     270 attack — evolution + energy concentration were NOT the gap.)
  3. **Floor test** — Lucario vs a **zero-damage** deck (Pokémon with no damaging attack, can't
     take a prize by KO): pilot wins only **70%**. A competent pilot must win ~100%.
- **THE BUG (found):** every loss to the zero-damage deck has the same signature — `my_deck=0`,
  `op_deck=22–42`, `my_prizeLeft=1–3` (ahead, often 1 KO from winning), 75–128 turns. **The pilot
  decks ITSELF out of won games.** `score_play` scores trainers **2200 unconditionally**, so with
  the Lucario deck's heavy draw/search engine (Carmine/Lillie/Pokégear/Dusk Ball ×4 each) it fires
  a draw card every turn regardless of need, milling its own deck to 0 while failing to close.
  **No prize/deck-race awareness.** → Fix `score_play`: gate draw/search on actual need (hand size,
  deck count) and prioritise closing when ahead. This is a concrete, fixable bug — not a wall.
- **`score_play` NEED-gate fix ✅ (legibility restored):** trainers now scored on need
  (`deck<=6 → 200`; else `2200 − 200·max(0,hand−4)` floored at 400) instead of flat 2200.
  - **Legibility RESTORED — the M6.2 blocker is resolved:** Lucario vs Iono **48% → 65%** (n=120;
    expert gave 76%, so it now clearly & directionally ranks Lucario > Iono). Lucario vs weak-aggro
    62%. **The pilot can now discriminate deck strength** → deck search can proceed.
  - Primary gates: vs random **82%** (no regression), vs Lucario expert **30%** (unchanged; still
    below the 40% gate — generic < card-specific, as expected).
  - **Residual leak (not fully fixed):** floor test (vs zero-damage) still **65%** — every loss is
    still a self-deck at ~5 prizes. Cause is now understood and is NOT a single bug: the pilot takes
    only ~1 KO/turn (wins avg 6.5 attacks/game, losses 5.0, though attacks were *available* ~30×
    either way) while grinding draw/search — it **races its own deck** and ~1/3 of unloseable games
    it decks one KO short. Fixing needs "focus & close" behaviour (keep one attacker loaded/active,
    stop over-developing) — harder than the draw-gate, and it also gates absolute strength (vs-expert).
- **Decision point:** the pilot is now competent for its PURPOSE (comparative deck *ranking*), which
  is all M6.2 needs. Fork: (A) proceed to M6.1 deck building now, revisit pilot "closing" only if
  search signal is too noisy; (B) invest one more "focus & close" pilot fix first (double value:
  tightens the floor AND raises vs-expert toward the 40% gate, which matters for the eventual ship).
  **→ Chose (B).**
- **`score_attack` close-faster fix ✅ (KO priority):** a KO attack now scores `2500 + 50·prize`
  (was `1500+100·prize`) — deliberately slotted BELOW free non-milling setup (ability 3000 / evolve
  2800 / attach-to-active 2600) but ABOVE benching / bench-attach / draw (≤2400), so once a prize is
  on the table the pilot takes it and ends the turn instead of over-developing (which mills its deck).
  Full regression suite (post-fix):
  | test | before | after |
  |---|---|---|
  | vs random | 82% | **95%** |
  | Lucario vs Iono (legibility) | 65% | **77%** (expert 76% — parity) |
  | Lucario vs weak-aggro | 62% | **80%** |
  | floor (vs zero-damage) | 65% | **75%** |
  | vs Lucario expert | 30% | 25% (n=40 noise) |
  - Legibility + weak-aggro + random all jumped — the pilot now converts winning positions well and
    **ranks decks in line with the expert.** Floor improved but residual self-deck remains (now an
    energy/setup *consistency* issue on bad openings, not the draw-overplay bug — a harder generic
    problem, diminishing returns).
  - **vs-expert stuck ~25–30%:** the generic-vs-specific gap on the expert's *own* deck (worst case).
    Closing fast even nudged it down (skips backup-attacker development that only matters vs a peer).
    This is the gap deck advantage must overcome — the M6 thesis — not a pilot bug to grind out here.
- **M6.0 VERDICT:** pilot is competent + deck-legible (77% = expert parity ranking Lucario>Iono;
  95% vs random). Good enough to drive deck search. Ship-strength (vs-expert) deferred to the
  deck-advantage bet. **→ Proceed to M6.1 (deck builder).**
